# ISU Main Campus 3D Model – Design

Date: 2026-10-20. Repository: `youngbrain85/isu-campus-3d` (main). Reference implementation:
`youngbrain85/white-oak-lake-dams-3d` (cloned to `D:\Projects\white-oak-lake-dams-3d`).

## 1. Goal

A browser-viewable (Three.js r170) and exportable (GLB) 3D model of the Indiana State University main campus,
Terre Haute, Indiana. Buildings with construction drawings are modelled in detail; every other OSM footprint
is a textured mass model; the ground is the Esri satellite mosaic with OSM roads, walks, parking, grass and trees.

## 3. Coordinate frame and units

* Origin: lat 39.4710, lon −87.4100 (campus centre, Dede Plaza area). Local tangent plane:
  `x_ft = (lon − lon0)·111320·cos(lat0)·3.28084`, `z_ft = −(lat − lat0)·110540·3.28084`, `y_ft` = height above ground.
* World axes: **X = east, Y = up, Z = south**, units feet (same convention as the reference viewer).
* Ground is a flat plane at y = 0 (campus is flat; NGVD ground ≈ 495–498 ft per the Nursing site plan benchmark).
  Drawing elevations are converted to height above ground with each building's first-floor level as datum.
* Every detailed building is modelled in its own local frame (drawing axes, feet) and placed by a 2-D similarity
  transform (translation + rotation, no scale) fitted to its OSM footprint; the fit residual is logged.

## 4. Pipeline

```
data/*.geojson, buildings.csv, imagery ──► tools/build_site.py ──► viewer/assets/site.json
                                                                    viewer/assets/ground_{0..3}.jpg (4 × 4096², local-plane reprojection of z20/z19)
                                                                    viewer/assets/trees.json
tools/gen_textures.py ─────────────────────────────────────────────► viewer/assets/*.jpg|png (procedural PBR: brick ×3 colours, limestone,
                                                                    precast, metal panel, curtain wall, roof membranes, asphalt, concrete, grass, tree sprites)
viewer/app.js (+ viewer/lib/*.js, viewer/buildings/*.js) ──────────► runtime scene; GLB export
tools/build.py + tools/index_template.html ─────────────────────────► viewer/index.html (CDN) / index_local.html / index_artifact.html
tools/shot.mjs (Playwright, local chromium) ────────────────────────► renders/*.png (1600×900), model/isu_campus.glb
```

### 4.1 `tools/build_site.py`
* Reprojects polygons/lines to the local frame; classifies: roads (by `highway`, width table: trunk/primary 48 ft,
  secondary 40, tertiary 36, residential 30, service 20, footway/cycleway 8), parking lots, grass/landuse, pitches,
  water, tree points (OSM `natural=tree`), plus **imagery-derived trees** (green-and-shadow classification of the
  z19 mosaic inside the campus bbox, thinned to ≥ 25 ft spacing) because OSM has only 61 tree nodes.
* Buildings: for every footprint writes polygon (outer + holes), `height_ft`, `levels`, `roof_rgb` (median of the z20
  mosaic inside the eroded footprint), `wall` class (brick-red / brick-brown / limestone / precast / metal / glass,
  from `building_facts.csv` or by era: pre-1960 brick+limestone, 1960–90 brick/precast, post-1990 brick+glass),
  `detail_level`. Detailed buildings are flagged so `app.js` skips their mass and calls the module instead.
* Ground tiles: samples the Web-Mercator mosaic at each local-plane pixel (0.35 ft ≈ 0.1 m/px from z20 where
  covered, z19 fallback), 4 tiles of 4096² px covering a 4800 ft square → JPEG q85 (~2 MB each).

### 4.2 Mass buildings (`viewer/lib/mass.js`)
* `THREE.Shape` from footprint → `ExtrudeGeometry` (height) with per-wall planar UVs (u = distance along the
  edge in ft, v = height in ft) so facade textures repeat per storey (storey height = height / levels).
* Facade texture = tileable material (brick etc.) with a window strip baked per storey (`gen_textures.py` makes
  `*_win.jpg` variants); roof = flat material tinted by `roof_rgb` with a 2 ft parapet lip; roof:shape `gabled`/
  `hipped` from OSM produce a simple ridge roof.
* Everything merged into a few `BufferGeometry`s per material (fast, exportable).

### 4.3 Detailed buildings (`viewer/buildings/<name>.js`)
One module per building, `export function build(ctx)` → `THREE.Group` in the building's local frame, plus
`export const placement = { anchor_ft:[x,z], rotation_deg, osm_id }`. Shared helpers in `viewer/lib/geom.js`:
`extrude(poly, h)`, `wall(p0, p1, h, {openings})`, `windowGrid(...)`, `canopy`, `stairs`, `parapet`, `column`.
Dimensions are read from the drawings (page renders at 150–300 dpi viewed during modelling); the OSM footprint is
used as the plan outline cross-check (drawing dimensions win; differences > 5 ft are noted in the README table).

### 4.4 Viewer (`viewer/app.js`, `tools/index_template.html`)
* Same skeleton as the reference: renderer, Sky, directional sun with shadows (shadow camera sized to the campus
  core, 4096 map), OrbitControls with ground clamp, collapsible translucent HUD (English), status/loader,
  `?shot=<preset>` headless mode, `window.exportGLB()`.
* Presets: `campus` (aerial), `hulman`, `rec`, `reeve`, `finearts`, `tech`, `welcome`, `nursing`, `myers`,
  `hmsu` (Hulman Memorial Student Union), `library` (Cunningham), `towers` (Sycamore Towers residence area).
* Toggles: Trees, Mass buildings, Labels (building-name sprites for named buildings), Ground imagery (off → flat
  colour), Shadows.
* Performance budget: ≤ 300 k triangles for masses + ground, ≤ 150 k per detailed building; instanced tree sprites.

### 4.5 Outputs
`viewer/` (index.html + app.js + assets ≤ 40 MB), `model/isu_campus.glb` (Release asset if > 100 MB),
`renders/<preset>.png` ×12, `README.md` (sources, per-building detail table, assumptions/limits), GitHub Pages
from `main` root with root `index.html` redirecting to `viewer/`.

## 5. Testing / verification
* `tools/build_site.py` self-checks: every detailed building's placement residual < 6 ft RMS; footprint count;
  ground tile georeference check (4 known intersections: 5th & Chestnut, 7th & Chestnut, 6th & Tippecanoe,
  9th & Cherry compared to OSM road centrelines, error < 10 ft).
* Headless render of every preset must reach `window.__ready` without page errors; screenshots are compared
  against the satellite crop of the same area (visual check).
* GLB opens in Windows 3D Viewer (file size, node count logged by `shot.mjs`).

## 6. Commits (pushed per stage)
1. inventory ✓ 2. data collection + buildings.csv 3. terrain/site + mass model + viewer skeleton
4. detailed buildings (one commit each) 5. presets, renders, GLB, README, Pages.

## 7. Assumptions and limits
* Imagery (Esri, ~2024) predates the Technology Building renovation; the model shows the 2025 drawings.
* Heights for non-drawing buildings are levels × storey height (estimate) unless published.
* Street View is not available (no API key); wall materials come from drawings, published photos and era rules.
* Interiors, MEP, below-grade work are not modelled.
